## 2. 原始 LLM Wiki 概念

| 项 | 值 |
| --- | --- |
| 作者 | Andrej Karpathy |
| 角色 | 概念源头——「persistent wiki / LLM 维护的 markdown 知识库」 |
| 链接 | `reference/llm-wiki.md`（本仓内）+ 原始 PR https://github.com/karpathy/llm-wiki |
| 引用 | 「LLM incrementally builds and maintains a persistent wiki」/ 「wiki is a persistent, compounding artifact」 / 「Optional: CLI tools」 |

**我们如何用**：
- 三层架构（raw sources / persistent wiki / agent）— 本仓 `spec-plugin-overview.md §2` 直接对齐
- 「wiki 中所有内容的目录」原则 — v2 Index.md 必须路由到所有 wiki 页（`02_读书笔记/` `03_问答区/` `11_entities/` `12_concepts/`，见 `spec-index-v2.md §1`）
- 「Optional: CLI tools」— 我们用 `sync-index.mjs` / `lint-wiki.mjs` / `qmd-detect.mjs` 等 CLI 脚本替代 LLM 手写聚合文件
- 「LLM never writes index manually」原则 — Karpathy 原文未直说但暗示，我们用 `<!-- sync-index:begin v2 -->` 标记块强制隔离

## 3. 参考实现

### 3.1 nashsu/llm_wiki（桌面 GUI 客户端）

| 项 | 值 |
| --- | --- |
| 仓库 | https://github.com/nashsu/llm_wiki |
| 当前版本 | v0.6.11 |
| 角色 | 桌面 GUI 客户端参考；`wiki/index.md` 设计参考 |
| 形态 | Tauri/Electron 桌面应用，与本仓 (Claude Code CLI plugin) 形态不同 |

**借鉴点**：
- `wiki/index.md` 用 4 列结构（标题 / 分类 / 关键概念 / 路径）— 本仓 `spec-index-v2.md §4` 直接对齐
- 桌面端不允许 LLM 手写 index（GUI 内有 atomic save + 标记块）— 我们用 `sync-index.mjs` 同样语义
- 桌面端 `wiki/index.md` 不含 entities / concepts 集中段（只在分类内分布）— 我们 v2 决定加 `## Entities` `## Concepts` 段（Karpathy 「everything in wiki」原则更紧）

**差异**：
- 我们路由 4 个目录（02/03/11/12）；桌面端路由只 02/03
- 我们 11/12 用 Kebab-case slug；桌面端 11/12 用下划线 slug

### 3.2 atomicstrata/atomicmemory（Python 单仓实现）

| 项 | 值 |
| --- | --- |
| 仓库 | https://github.com/atomicstrata/atomicmemory |
| 角色 | `packages/llmwiki/` 子目录参考；monorepo 形态参考 |
| 形态 | Python 多包 monorepo（与本仓单仓 Node.js 不同） |

**借鉴点**：
- `packages/llmwiki/` 内文件命名 `Index.md` + 标记块，与我们 v2 同语义
- index 重建走 git commit + LLM 不可见的 hash 校验 — 我们用 `sync-index.mjs --check` 校验
- 「写入即提交」原则（每次 ingest 强制一次 commit）— 本仓 `obsidian-collacting/SKILL.md` 强制步骤「与主任务同次 commit 完成」对齐

**差异**：
- atomicmemory 把 sync 脚本与 LLM 调用耦合在一个 Python 类；我们 LLM 调用走 Claude Code sub agent，CLI 脚本只做 I/O（更易测试）
- atomicmemory `packages/llmwiki/` 是一组；我们是单 plugin

### 3.3 green-dalii/obsidian-llm-wiki（Obsidian 插件）

| 项 | 值 |
| --- | --- |
| 仓库 | https://github.com/green-dalii/obsidian-llm-wiki |
| 角色 | Obsidian 插件形态参考；Tiered duplicate detection 设计参考 |
| 形态 | Obsidian 插件 (TypeScript)，与本仓（Claude Code CLI plugin）形态不同 |

**借鉴点**：
- **三档 dedup**（Tier 1 alias → Tier 2 编辑距离 → Tier 3 LLM 判定）— 本仓 `obsidian-collacting/SKILL.md` 阶段 3 任务 E 直接对齐
- `aliases:` 必填 ≥ 1 — 本仓 `10_schema/config.md §4` entity 模板强制
- `sources:` 数组反向链接 + 去重 — 本仓 `knowledge-graph-sync/SKILL.md` Phase 3 同语义

**差异**：
- green-dalii 是 Obsidian 内 TypeScript 插件（运行时 Obsidian 内）；我们是 Claude Code CLI plugin（运行时终端/IDE 内）
- green-dalii 把 LLM 调用嵌在插件内；我们走 Claude Code sub agent（独立进程）

## 4. 配套工具（mcp / cli）

### 4.1 tobi/qmd（MCP 向量召回）

| 项 | 值 |
| --- | --- |
| 仓库 | https://github.com/tobi/qmd |
| 角色 | 大 vault（≥500 / ≥3000 笔记）的 BM25+ 向量混合检索 |
| 形态 | npm CLI + MCP server |
| 文档 | `docs/superpowers/specs/spec-query.md §v3` / `docs/superpowers/plans/2026-08-29-llm-wiki-query-v3-design.md` |

**我们如何用**：
- `scripts/qmd-detect.mjs` 在 SessionStart hook 注入 system context 决定 `effective_path`
- 三档决策：small (<500) → 强制 grep；medium (500-3000) → qmd 装了用 qmd；large (≥3000) → qmd 装了用 qmd + 强提示
